Search-Performance Opportunity Scoring for Content Review

A repeatable decision-support framework using the FlyRank ML Internship search warehouse

FlyRank ML Internship Capstone · March 2026 Data Release

Abstract

This study asks whether search-performance signals can be combined into a repeatable scoring system that helps prioritize content pages for review. Using the March 2026 FlyRank ML Internship search warehouse, the analysis uses Google Search Console-derived impressions, clicks, average position, click-through rate, and an observed decline label. A transparent logistic regression model is evaluated against a majority-class baseline using the same stratified test split, while a separate weighted opportunity score converts observable signals into a ranked content-review queue. The classification model achieves the same accuracy as the majority baseline in this validation setup, indicating that the simple model does not provide measurable accuracy improvement over the baseline. The resulting opportunity score is therefore framed as a directional decision-support and prioritization mechanism rather than a guaranteed predictor of traffic growth or a causal explanation of search-engine behavior.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially be improved, but limited time to investigate every page. The practical decision supported by this analysis is therefore:

Which content pages should a content team investigate first for potential improvement, rewriting, or monitoring?

The capstone focuses on the Refresh / Content Opportunity Scoring lane. Rather than attempting to explain Google's ranking system, the analysis identifies observed search-performance patterns and converts them into a repeatable review-prioritization framework.

The output is intended to help organize editorial investigation. A high opportunity score indicates that a page has a combination of observable signals that make it worthy of review; it does not guarantee that changing the page will improve traffic or rankings.

2. Data

The analysis uses the March 2026 release of the FlyRank ML Internship search warehouse, specifically the fact_content_daily_performance data.

The warehouse was queried using DuckDB with secure Hugging Face authentication. The analysis filters to records where gsc_data_available = TRUE, ensuring that the analyzed records have usable Google Search Console performance signals.

3. Methodology

Features

Four input features are used:

Feature Purpose
GSC impressions Measures search visibility volume
GSC clicks Measures search-result clicks
GSC average position Measures observed search position
CTR Calculated as clicks divided by impressions

Target Label

The target is decline_label, a binary indicator representing the previously defined observed content-traffic decline condition.

Model

A logistic regression classifier was selected because it is simple, transparent, and reproducible. Features were standardized using a scaler fitted only on the training data.

Validation

The dataset was divided into an 80% training set and a 20% test set using stratification and a fixed random seed of 42. Both the majority-class baseline and logistic regression model were evaluated on the same held-out test set.

Baseline

The baseline uses a majority-class classifier. This provides a simple reference point for evaluating whether the predictive model adds measurable classification value.

Leakage Checks

  • The target label is excluded from the feature matrix.
  • The target is not used during feature scaling.
  • Scaling is fitted only on training data.
  • The baseline and model use the same test set.
  • No future search-performance information is intentionally introduced into the feature matrix.

5. Limitations & Honest Framing

  • Association, not causation: The analysis identifies relationships in observed search-performance data. It does not establish causal mechanisms.
  • Limited temporal window: The analysis focuses on the March 2026 release and therefore does not represent all seasons or future periods.
  • No Google algorithm claims: The analysis does not reverse-engineer or prove how Google's ranking systems work.
  • Prioritization, not prediction: The opportunity score is a review-prioritization heuristic and does not guarantee future traffic or ranking improvements.
  • Human review required: Recommendations should be investigated by content and domain experts before any editorial changes are made.
  • Model performance: The logistic regression classifier did not outperform the majority baseline on accuracy in this validation setup.

6. Ranked Recommendations

The opportunity scoring engine combines observable search-performance signals into a single prioritization score.

Opportunity Score

The score uses weighted percentile ranks:

Signal Weight
Visibility / impressions 35%
Position risk 25%
CTR opportunity 20%
Observed decline signal 20%

The resulting score is scaled to a 0–100 range. Higher scores indicate greater prioritization according to the defined scoring framework.

Reason Codes

Reason Code Recommended Action
HIGH_VISIBILITY_DECLINE Prioritize for content refresh or rewrite investigation.
POSITION_RISK Review content and search-position risk signals.
LOW_CTR_OPPORTUNITY Investigate search-result presentation and metadata opportunities.
MONITOR Continue monitoring rather than immediately changing the content.
Important: These reason codes are operational recommendations generated from the scoring framework. They are not guarantees of future performance.
